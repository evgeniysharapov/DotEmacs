* Introduction
Motivational points:
  - Everything, including customization modules, is loaded using
    =use-package=. Because =use-package= wasn't a part of Emacs until
    24.5 this configuration /as is/ is not working with 24.4. However
    it could be easily modified by just installing =use-package= via
    ELPA at the beginning.
  - Having configuration in =Emacs-Lisp=. I used to have literate
    programming style configuration using =org-babel=, but seems like
    complications: tricky navigation, swithing to source editing and
    back, reloading issues, performance hit outweigh the benefit of
    having a good documentation and code visibility manager.

Since configuration is changing all the time, there's no point to
describe it at length. Just some of the highlights.

* Some Shortcuts

** Help

   * =C-h M-k= describe keymap
   * =C-h C-c= describe character at point
   * =C-h C-b= describes keys customizations

** Some Useful Keymaps

 These could be explored further via =C-h M-k= for example

   * =C-x f= file opening map
   * =C-x t= toggling keymap
   * =C-x w= windows management keymap
   * =C-z= personal keymap

** Buffer Visibility / Navigation
   * =C-z /= changes visibility via =hide-lines=
   * =M-s o= shows occurences of a string in a buffer (=occur=)
   * =M-s O= multi buffer occur (moccur)
   * =M-g j= starts =avy-jump=

** Miscellaneous
   * =C-x K= kill this buffer
   * =C-M-:= start/switch to IELM with current buffer
   * =M-z= is zapping up to a character, =M-Z= zaps to character. Zapping backward is via negative universal argument.

** Dired
   * Opening a directory (=RET=) reuses the current dired buffer instead of
     creating a new one. Opening a file (=RET=) still visits it in a new buffer.
   * =^= goes to the parent directory, also reusing the current buffer.

** GitHub Copilot
   * =M-RET= triggers a completion suggestion at point.
   * While a suggestion is shown, =M-RET= accepts it and =C-g= dismisses it.
   * Copilot is only active once its language server has been installed via
     =M-x copilot-install-server= (checked on buffer startup to avoid errors
     before that step has been run).

** Debugging (=dap-mode=)
   * =C-z . d= starts a debug session (=dap-debug=).
   * =C-z . b= toggles a breakpoint at point.
   * =C-z . B= deletes all breakpoints.
   * =C-z . l= lists all breakpoints in a UI buffer. There, =RET= jumps to
     the breakpoint at point and =d= deletes it.
   * =C-z . h= opens the =dap-hydra= menu for stepping (next/step-in/step-out),
     continuing, and other debug actions. It also opens automatically
     whenever execution stops at a breakpoint.
   * For Go, =dlv= (Delve) is required and must support the installed Go
     version; see https://github.com/go-delve/delve for compatibility.

* macOS Notes
** pdf-tools on macOS 13 (Intel)
   Homebrew publishes no bottles for macOS 13 on Intel, so everything is
   compiled from source with Apple clang 15, which lacks some C++23 library
   features. =pdf-tools= needs the =epdfinfo= server, which links against
   =poppler=. Building it takes three steps:
   1. Build =poppler= with a newer compiler. The stock build fails in
      =GPGMECryptoSignBackend.cc= (=std::ranges::contains= is missing from the
      system libc++), so use the Homebrew LLVM:
      : brew install --cc=llvm_clang poppler
   2. =epdfinfo= is built by =pdf-tools= from Emacs on first use. Its
      =poppler.pc= requires =libcurl >= 8.5=, but pkg-config finds macOS's 7.x
      first because Homebrew's =curl= is keg-only. The =pdf-tools= block in
      =init.el= sets =PKG_CONFIG_PATH= so =/usr/local/opt/curl= comes first.
   3. If the server has to be rebuilt by hand (for example after a =pdf-tools=
      update), run from the package's =build/server= directory:
      : export PKG_CONFIG_PATH=/usr/local/opt/curl/lib/pkgconfig:/usr/local/lib/pkgconfig
      : autoreconf -i && ./configure -q --bindir=<pdf-tools dir> && make && make install
   Keep =llvm=: =--cc=llvm_clang= needs it, and =rust= and =lld= depend on it.
